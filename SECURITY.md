# Безопасность

## Сообщить об уязвимости

Не открывай публичный issue. Напиши на `security@<домен>` с описанием проблемы и
шагами воспроизведения. Ответ в течение 72 часов.

Если уязвимость позволяет прочитать чужую переписку или деанонимизировать
ребёнка — пометь письмо словом «срочно».

---

## Модель угроз

Проект защищает четыре вещи, в порядке важности:

1. **Анонимность ребёнка.** Никто, включая администратора сервера, не должен
   узнать, кто именно написал
2. **Тайну переписки.** Чужой человек не должен прочитать чужой диалог
3. **Физическую безопасность ребёнка у экрана.** Переписку не должен увидеть
   тот, кто в любой момент возьмёт устройство в руки
4. **Доступность сервиса.** Ребёнок в кризисе не должен упереться в недоступный
   сайт

Основные противники: агрессор из окружения ребёнка с доступом к его устройству;
любопытный человек с доступом к серверу или бэкапу; автоматизированный флуд.

## Что уже сделано

**Анонимность**

- регистрации нет, персональные данные не запрашиваются нигде в интерфейсе
- диалог привязан к случайному 256-битному токену; в базе лежит только его
  `sha256`, поэтому из дампа нельзя восстановить токен и войти в чужой разговор
- психолог видит псевдоним вида «Гость-4821»
- IP-адреса в базу не записываются

**Защита у экрана**

- разговор по умолчанию помнится на устройстве, чтобы ребёнок мог вернуться;
  режим отключается одним переключателем, и тогда переписка живёт только до
  закрытия вкладки
- токен протухает через 30 дней без захода, диалоги на сервере удаляются через
  `CONVERSATION_TTL_DAYS` дней без сообщений
- «Быстро закрыть» и тройной `Esc` уводят на нейтральный сайт через
  `location.replace`, не оставляя страницу в кнопке «Назад»; разговор при этом
  сохраняется — для полного стирания есть отдельное «Удалить и выйти»
- кнопка полного удаления диалога стирает данные и на сервере
- `X-Robots-Tag: noindex` — сайт не попадает в поисковую выдачу

**Транспорт и заголовки**

- HTTPS с автоматическим сертификатом и HSTS
- CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`
- в продакшен-конфигурации наружу открыт только Caddy; база и API — во
  внутренней сети Docker

**Приложение**

- пароли психологов: bcrypt, cost 12; в базе только хеши
- вход в панель: не более 5 попыток в минуту с адреса
- создание диалогов: 30 за 10 минут с адреса
- в сокете token bucket на 8 сообщений с пополнением раз в секунду
- валидация всех входящих полей, длина сообщения ограничена 2000 символами
- Vue экранирует текст сообщений, `v-html` не используется

## Известные пробелы

Перечислено честно и по приоритету. Пока список не закрыт, сервис держится
закрытым для посторонних.

| Пробел | Риск | Что нужно |
|---|---|---|
| Сообщения лежат в базе открытым текстом | доступ к серверу или бэкапу раскрывает все переписки | шифрование тома, шифрование поля сообщения |
| Разговор переживает перезагрузку устройства | переписку может открыть тот, кто возьмёт телефон ребёнка | предложить ребёнку короткий код возврата вместо постоянного токена |
| JWT психолога живёт 12 часов и не отзывается | украденный токен работает до истечения | список отозванных сессий, выход из аккаунта |
| Одна учётка психолога из `.env` | не масштабируется на команду, нет 2FA | раздел управления пользователями, роли, двухфакторная аутентификация |
| Нет журнала действий специалистов | не видно, кто какой диалог открывал | аудит-лог с неизменяемыми записями |
| Счётчики ограничений в памяти процесса | при нескольких экземплярах лимиты разъезжаются | Redis |
| Нет защиты от целевой атаки на доступность | сайт можно положить флудом | Cloudflare или аналог перед сервером |
| Шрифты грузятся с Google Fonts | IP посетителя уходит третьей стороне | самостоятельная раздача `.woff2` |
| Нет мониторинга | падение ночью никто не заметит | проверка `/api/health`, оповещения |
| Нет резервных копий | потеря тома `db-data` необратима | ежедневный `pg_dump` на отдельный сервер |

## Правовая часть

Переписка ребёнка о травле и самочувствии — сведения о здоровье, то есть
специальная категория персональных данных по 152-ФЗ, даже если имя не
запрашивается. Отсутствие регистрации снижает риск, но не выводит проект
из-под закона.

До открытия публичного доступа нужны:

1. Проверка дипломов психологов и договоры с ними
2. Письменный протокол эскалации: действия при угрозе жизни, при насилии в
   семье, при признаках преступления против ребёнка
3. Политика конфиденциальности и пользовательское соглашение
4. Супервизия специалистов и регулярный разбор сложных случаев
5. Оценка необходимости уведомления Роскомнадзора об обработке данных

Отдельное правило, зашитое и в текстах интерфейса: сервис не заменяет взрослого
рядом с ребёнком, а помогает найти того, кому можно доверять. Переписка не
должна подталкивать ребёнка скрывать происходящее от безопасных взрослых.
